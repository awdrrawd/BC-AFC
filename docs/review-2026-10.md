# AFC 程式審查與加固紀錄（對照 BC R133）

## 1. 架構摘要
- `main.js` 防重複載入 → `app.js` → `core/core-init.js` 兩階段初始化（載入期 / 登入後）。
- 資料：本人主資料在 `ExtensionSettings.AFC_Data`，`OnlineSharedSettings.AFC` 只是公開投影；心鎖在 `ExtensionSettings.AFC_HeartLock`。
- 通訊：同房 1 對 1 Hidden（`AFC::Beep` 可靠傳輸、`HeartLock::*`）；戀人與鎖摘要走 `OnlineSharedSettings`＋ AccountBeep（`afcBeep`，戀人房名）。
- Hook 統一由 `hooks/registry.js` 管理並可整批釋放。

## 3. R133 相容核對
52 個 hook 目標函式全部存在；關係子選單、`DialogCanUnlock` 簽名、好友列表關係欄、`AccountBeep` 對未知 `BeepType` 的忽略行為皆與 AFC 假設相符。

## 4. 第二輪（依維護者決策）
已完成：
1. **清除死碼**：整套鎖定授權（`AFCLockAccessOn`、`SYNC_REQUEST/GRANT`、`LOCK_ACCESS_OFF`、`DialogCanUnlock` 的 `AFCLoveLock/AFCTimerLock` 分支、`ServerDisconnect` hook、`syncWithOnlineLovers`）。舊客戶端送來的三種握手訊息會被靜默忽略。`/afc-status` 的「線上」改為真實的線上戀人數。
2. **AFC 訊息 1 對 1**：`AFC::Beep`、`HeartLockApply/Update/Remove/Request` 皆加頂層 `Target`。
3. **戀人資料與鎖走 OnlineSharedSettings**：移除 P2P `AFC::Sync` 廣播與接收端；他人身上的鎖以 `OnlineSharedSettings.AFC_HeartLock` 公開摘要為權威（存在與否、lockId）。
4. **私密細節按需請求**：開啟他人心鎖面板時才送 `HeartLockRequest{Group}`；穿戴者確認請求者是掛鎖者或授權關係，只回該部位、只回請求者。不再廣播整份鎖設定（含 note）。

留待評估：
- `getSharedSettings()` 有副作用（寫入、同步、彈確認視窗），建議拆成純讀取與明確遷移流程。
- 其餘僅限遊戲內驗證的項目見第 6 節。

## 6. 驗證
`npm run lint`、`npm test`（111 項）、`npm run build`、`npm run check:assets` 皆通過。

**必須遊戲內實測**（單元測試無法涵蓋伺服器行為）：
1. 頂層 `Target` 的 Hidden 訊息確實只送達對象：申請 → 接受 → 升格 → 分手 → 恢復，全流程。
2. 一方修改戀人／鎖權限後，同房另一方不需任何查詢即可看到更新（依賴伺服器對 `OnlineSharedSettings` 的房內同步；舊 `AFC::Sync` 原為 EBC 等環境的容錯，已移除）。
3. 開啟他人的心鎖面板：掛鎖者看得到 note／計時；無權限者只看到摘要；掛鎖者編輯後面板刷新。
4. 與仍使用舊版 AFC 的對象互動：舊版對你送的 Sync/握手被忽略；舊版不會回應新的 `HeartLockRequest`（細節欄位顯示空白，摘要仍正常）。
